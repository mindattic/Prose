Dynamic Context Memory:
Beat-Scoped, Drift-Free Context Assembly for Long-Form Narrative Generation

Date2026-07-16
ClassificationSoftware / AI Systems
Abstract

A system and method for generating and maintaining ephemeral markdown documents from a persistent source repository (database, in-memory object, or equivalent) for use by a large language model, wherein each document remains resident only until it has not been accessed for a configurable number of operations — a "beat," the atomic unit of narrative generation — at which point it is erased from the working set while its source data is preserved in the underlying repository and may be re-materialized on demand.

I.Field

Context management for large language model inference in long-form narrative generation — specifically, systems and methods for assembling a scoped, relevance-ranked context window on a per-beat basis, preventing context drift while maintaining coherence across extended works.

II.Background

When an LLM's context window is loaded with the entirety of a story's supporting documentation, it exhibits context drift: contradictions of prior facts, loss of character voice consistency, and hallucination of world details. Prior approaches load all context (causing drift) or load none (producing incoherence). What has been absent is a system that maintains a narrow, current-beat-relevant subset of the full corpus — loading documents when relevant, releasing them when not.

A "beat" is the atomic unit of narrative generation: a single story event, scene fragment, or action. This beat-level granularity is finer than chapter-level and coarser than token-level, matching the natural coherence unit of narrative prose.

III.Key Mechanism — Five-Pass Retrieval Pipeline

For each beat, five ordered retrieval passes contribute documents to a tiered LRU context stack:

  • Pass 0 — Entity Inference: Scans the beat goal text for named entity references; materializes compact .md documents from structured DB records for any found. Runs before the candidate query so fresh entity docs participate in passes 3–5.
  • Pass 1 — Always Tier: Universal invariants pinned to every context; never evicted.
  • Pass 2 — Node Tier: Story bible scoped to the active story; evicted on story change, not beat count.
  • Pass 3 — Keyword Trigger: Documents whose declared triggers field intersects the beat text, with stopword filtering.
  • Pass 4 — Semantic Embedding: Top-K documents by vector similarity, subject to a minimum threshold.
  • Pass 5 — Relational Cascade: For each resident document, loads declared related: neighbors one level deep — no recursive fan-out.

Entity documents are stored as database-only rows (FilePath="", SyncedBy="inferred") — never written to disk. A SHA-256 hash gate makes re-materialization of unchanged entities a no-op. Documents carry YAML frontmatter declaring tier:, triggers:, and scope: fields that override heuristically derived classifications without code changes.

IV.Informal Claims
  1. Claim 1 — Independent (Method)

    A computer-implemented method for assembling a context window for LLM inference comprising: receiving a generation target specifying a narrative unit (beat); executing ordered retrieval passes comprising at least a universal-document pass, a story-scoped pass, a keyword-trigger pass, a semantic-embedding pass, and a relational-cascade pass; assembling retrieved documents into a token-budgeted block; and evicting documents not refreshed within a configurable beat-count threshold.

  2. Claim 2 — Tiered Eviction

    The method of claim 1, wherein documents are classified into tiers: always (never evicted); node (evicted on story change, not beat count); topic (evicted after N beats without retrieval).

  3. Claim 3 — Entity Materialization

    The method of claim 1, wherein, prior to the keyword-trigger pass, entity references are inferred from the generation target and a context document is materialized from a structured database record without producing a corresponding disk file, made immediately available to subsequent passes in the same invocation.

  4. Claim 4 — Hash-Gated Materialization

    The method of claim 3, wherein materialization computes a hash of the entity record and is a no-operation when the hash matches a stored value.

  5. Claim 5 — Relational Cascade

    The method of claim 1, wherein the relational-cascade pass reads a relationship field on resident documents and loads related documents not already resident, with cascade depth capped at one level.

  6. Claim 6 — Frontmatter Override

    The method of claim 1, wherein documents carry structured metadata declaring explicit tier, trigger terms, or scope, overriding heuristically derived values without code modification.

Structural Blueprint System:
Pre-Prose Structural Commitment as AI-Fiction Countermeasure

Date2026-07-16
ClassificationSoftware / AI Systems / Creative Computing
Abstract

A system and method for committing nine interdependent structural dimensions of a long-form narrative — subplot plan, temporal scheme, resolution mode, moral polarity, escalation curve, event type palette, form device, ending style, and intertextual anchors — in a single generation pass before any prose is written, with mandatory outlier-seeking and per-beat structural slice injection at write time.

I.Field

Structural planning and countermeasures for AI-generated long-form narrative — specifically, methods for pre-committing narrative structure parameters to reduce statistical detectability and prevent structural drift across generation calls.

II.Background

Research (arXiv 2604.03136, UMD/Google DeepMind 2025, corpus of 61,608 stories) establishes that AI-generated fiction is classifiable at 93.2% accuracy from narrative-structure decisions alone — not prose style. The strongest single AI marker is internal-understanding resolution (a character "understands" or "realizes" something), present in 47% of AI stories vs. 27% of human stories. This makes structural pre-commitment — made before any prose — the only effective systemic countermeasure.

III.Key Mechanism

A single LLM call commits nine structural parameters simultaneously before prose generation begins. Critically, the call's Step 0 is mandatory outlier-seeking: the model enumerates the three most obvious resolutions for the given premise and explicitly forbids them before designing, grounded in the empirical finding that human stories are statistical outliers 57.8% of the time.

The nine committed dimensions are: SubplotPlan (beat indexes carrying the B-story), TemporalPlan (linear/frame/nonlinear with cut beat index), ResolutionMode (external/unresolved/mixed — internal-understanding is explicitly excluded as a forbidden value), MoralPolarity (ambivalent/clear), EscalationCurve (per-unit integer 1–10 array, non-decreasing act-over-act), EventTypePalette (per-unit event type with revelation mode), FormDevice (optional formal originality choice), EndingStyle (avalanche/quiet with NoEpilogue flag), and IntertextualAnchors (3–5 named in-world entities drawn via semantic embedding, k=8).

At write time, BuildBeatInjectionAsync() injects the relevant per-unit slice into each prose generation prompt. Granularity auto-scales at ChapterGranularityThreshold = 60 beats: short works plan per-beat; book-scale works plan per-chapter. A RetrofitAsync() path infers the blueprint from already-written prose, enabling the audit service to identify structural deviations from the story's own implied commitments.

IV.Informal Claims
  1. Claim 1 — Independent (Method)

    A computer-implemented method for generating long-form narrative comprising: enumerating and forbidding the N most statistically probable structural resolutions for a given narrative premise before designing the structure; simultaneously committing at least subplot plan, temporal scheme, resolution mode, moral polarity, escalation curve, event type palette, and ending style in a single generation pass before any prose unit is written; and injecting a per-unit structural slice derived from the committed blueprint into each prose generation call.

  2. Claim 2 — Prohibited Resolution Mode

    The method of claim 1, wherein resolution mode excludes internal-understanding resolution as a permitted value, based on empirical detectability data establishing it as a marker of AI-generated content.

  3. Claim 3 — Non-Decreasing Escalation

    The method of claim 1, wherein escalation curve is represented as a non-decreasing integer array across act boundaries, and wherein violation of the non-decreasing constraint is detected and reported by a post-generation audit service.

  4. Claim 4 — Granularity Auto-Scaling

    The method of claim 1, wherein planning granularity is automatically set to per-unit for works below a threshold beat count and to per-chapter for works above that threshold.

  5. Claim 5 — Retrofit Inference

    A method for inferring structural blueprint parameters from already-written prose, enabling audit of a completed narrative against its own implied structural commitments without a prior explicit planning pass.

Multi-Provider Expert Persona Quorum Review:
Stratified Ballot System with Psychometric Shaping and Audience Clustering

Date2026-07-16
ClassificationSoftware / AI Systems / Quality Evaluation
Abstract

A two-tier stratified review system that distributes scored reading ballots across a library of over 1,000 distinct reader personas and multiple cloud LLM providers in round-robin fashion, shapes each persona's evaluation criteria via Big Five psychometric profiles, selectively upgrades a proportion of ballots to full prose criticism based on score distribution, and clusters ballots into emergent audience segments for per-beat decision synthesis.

I.Field

Quality evaluation of LLM-generated long-form narrative — specifically, methods for multi-perspective scored review that varies both reader identity and model identity across ballots to reduce systematic bias.

II.Key Mechanism

The system draws from a 1,000+ persona library and round-robins assignments across multiple trusted LLM providers (claude-api, claude-team, openai, gemini, deepseek) so both model identity and reader viewpoint vary independently across ballots. This controls for provider-specific aesthetic biases that would otherwise distort aggregate scores.

Tier 1 issues cheap score-only ballots: each persona returns score (1–100), flow, prose_gripe (≤10 words), logic_gripe (≤10 words), and beat_scores (per-beat 1–5). Tier 2 upgrades the most informative ballots to full prose reviews: SelectInformative() selects k×3/10 harshest, k×3/10 most generous, and k×4/10 from the median band — capturing the full distribution rather than sampling uniformly.

Each persona prompt incorporates a Big Five psychometric profile summary: high Openness tolerates strange/lyrical content; high Conscientiousness is impatient with structural looseness; high Neuroticism feels stakes sharply. Ballots are clustered via a reviewer×beat score matrix into emergent audience segments; a Pareto/contested per-beat decision report surfaces systematic disagreements. A structural diagnostic pre-flight gates ballot spending — blocking pre-flight failures return immediately without consuming API calls.

III.Informal Claims
  1. Claim 1 — Independent (Method)

    A method for quality evaluation of LLM-generated narrative comprising: selecting personas from a library; distributing evaluation ballots across multiple LLM providers in round-robin fashion; issuing tier 1 score-only ballots and tier 2 full-prose ballots; selecting ballots for tier 2 upgrade by sampling the harshest, most generous, and median-band proportions of tier 1 results; and clustering ballots into audience segments.

  2. Claim 2 — Psychometric Shaping

    The method of claim 1, wherein each persona prompt incorporates a Big Five psychometric profile that modulates evaluation criteria across dimensions including openness, conscientiousness, and neuroticism.

  3. Claim 3 — Structured Tier 1 Ballot

    The method of claim 1, wherein tier 1 ballots require per-narrative-unit scores in addition to an overall score, enabling per-beat quality analysis without the token cost of full prose criticism.

  4. Claim 4 — Pre-Flight Gating

    The method of claim 1, wherein a structural diagnostic pre-flight executes before any ballot is issued, and blocking pre-flight failures terminate evaluation without consuming LLM inference budget.

Plant/Payoff Lifecycle Registry:
Three-Status Tracking with Transparency Certification and Orphan Audit

Date2026-07-16
ClassificationSoftware / AI Systems / Narrative Computing
Abstract

A system for registering narrative plant/payoff pairs as first-class records with a three-status lifecycle (planned, seeded, paid-off), two separate explicit linking operations binding each to authored prose beats, a transparency certification step distinct from payoff completion, and an automated audit identifying three distinct failure categories: orphaned plants, opaque payoffs, and coverage gaps.

I.Field

Narrative coherence tracking in long-form AI-assisted generation — specifically, systems for managing the lifecycle of seeded narrative details (plants) and their later fulfillments (payoffs) to ensure reader reward without breaking first-pass comprehension.

II.Key Mechanism

The system enforces a fundamental narrative invariant: "reward re-reading without requiring it" — first-pass comprehension must be complete without the plant, but the returning reader gains additional meaning. Each pair stores a PlantDescription, PayoffDescription, and Category.

Linking is two separate acts: LinkPlantBeatAsync(id, beatId) binds the plant to its prose beat after writing; LinkPayoffBeatAsync(id, beatId) binds the payoff separately. This creates a three-status lifecycle: planned (neither beat linked), seeded (plant beat linked, payoff null), paid off (both linked). Separately, SetTransparencyAsync() certifies whether a cold reader can follow the payoff — a payoff marked paid-off but not certified transparent generates a TRANSPARENCY ISSUE flag and is injected into beat generation prompts as a constraint. AuditAsync() identifies three failure categories independently, enabling targeted rather than undifferentiated quality reports.

III.Informal Claims
  1. Claim 1 — Independent (System)

    A system for tracking narrative plant/payoff pairs comprising: a registry associating a plant description and payoff description with a category and story identifier; two separate operations linking plant and payoff each to distinct prose unit identifiers; a transparency certification operation distinct from payoff completion; and an audit operation identifying orphaned plants, opaque payoffs, and coverage gaps as separate failure categories.

  2. Claim 2 — Generation Context Injection

    The system of claim 1, wherein registered pairs and their transparency status are injected into prose generation prompts as authorial constraints for subsequent narrative units.

  3. Claim 3 — Commandment Enrichment

    The system of claim 1, wherein the live plant/payoff registry data is injected into specific quality commandment evaluation prompts, providing factual evidence for commandments that assess narrative reward and reader re-read value.

Beat-Mode Classification with Prose Rhythm Directive Assignment:
Priority-Ordered Keyword Quorum with Position-Proportional Override

Date2026-07-16
ClassificationSoftware / AI Systems / Natural Language Generation
Abstract

A two-stage system that first classifies each narrative beat into one of six modes (Combat, Emotional Climax, Dialogue, Transition, Revelation, Narrative) via priority-ordered keyword arrays with associated confidence scores, then assigns one of five prose rhythm directives (Breathe, Flow, Tighten, Strike, Settle) via fractional narrative position with keyword-based override, and injects multi-line craft directives including explicit prohibitions into the generation prompt.

I.Field

Adaptive prose style generation — specifically, methods for determining and injecting per-beat structural prose constraints based on the beat's semantic content and position within the overall narrative arc.

II.Key Mechanism

Stage 1 (Mode Classification): Five keyword arrays are tested in strict priority order, each with a calibrated confidence score. Combat (25 terms, confidence 0.85) supersedes Emotional Climax (13 terms, 0.80) supersedes Dialogue (27 terms, 0.75) supersedes Transition/Revelation (7 terms each, 0.70). A null beat goal defaults to Narrative at 0.50. Classification is logged to BeatModeLog with mode, confidence, and detection method for cross-universe analytics.

Stage 2 (Rhythm Assignment): GetPacing(beatIndex, totalBeats, beatGoal) computes a fractional position and maps to one of five PaceMode values via threshold ranges (Breathe <0.15, Flow <0.40, Tighten <0.70, Strike <0.85, Settle ≥0.85). A keyword override layer then supersedes the positional assignment for terms like fight/chase → Strike, discover/arrive → Breathe, aftermath/grief → Settle. Each mode maps to a multi-line ProseGuidance string injected into the LLM prompt, including explicit prohibitions — for example, Settle mandates a hard stop against narrator moral gloss ("do NOT have the narrator summarize what the scene meant").

III.Informal Claims
  1. Claim 1 — Independent (Method)

    A method for adaptive prose generation comprising: classifying a narrative unit into a beat mode by testing keyword arrays in strict priority order with associated confidence scores; assigning a prose rhythm mode by computing a fractional position within the total narrative length and applying keyword-based overrides; and injecting a prose directive string including explicit craft prohibitions into the generation prompt.

  2. Claim 2 — Priority-Ordered Keyword Quorum

    The method of claim 1, wherein beat mode classification resolves by the first keyword array that produces a match, ensuring higher-priority modes supersede lower-priority modes regardless of match strength.

  3. Claim 3 — Prohibition-Bearing Directives

    The method of claim 1, wherein at least one rhythm directive includes explicit prohibitions on generation behavior — structural rules expressed as "do NOT" constraints — in addition to prescriptive stylistic guidance.

  4. Claim 4 — Persistent Mode Logging

    The method of claim 1, wherein classified mode, confidence score, and detection method are persisted per narrative unit to a log table enabling cross-story and cross-universe pattern analysis.

Voice Rule Harvest from High-Scoring Editorial History:
Three-Source Evidence Mining with Staged Commit-Before-Mutate Application

Date2026-07-16
ClassificationSoftware / AI Systems / Adaptive Generation
Abstract

A system and method for automatically extracting prose voice rules from three evidence sources — temporal beat-version edit diffs, explicit author directives, and finished prose text — via LLM distillation into a staged change log, with a commit-before-mutate application pattern ensuring no partial state on failure, and automatic trigger when a story's review score exceeds a threshold.

I.Field

Adaptive voice rule generation for AI-assisted narrative systems — specifically, methods for inferring generalizable prose style constraints from observed author editing behavior and review performance.

II.Key Mechanism

The service mines three evidence sources per story node: (1) temporal beat-version edit history — for each beat with two or more versions, the oldest (originally generated) text is diffed against the current final text, capturing up to 24 (position, before, after) edit pairs; (2) author directives logged to VoiceChangeLog as observed-status entries; (3) finished prose text (sampled to 16,000 chars).

An LLM call at temperature 0.2 distills the smallest set of concrete, verifiable rules from these inputs, targeting one of four named live rule stores: literary_rules.prohibitions, literary_rules.paragraph_requirements, tone_bible.tone_rules, tone_bible.dialogue_rules, or a per-character narration voice target. All outputs enter the change log as Status="proposed" — nothing touches the live stores until ApplyAsync() is explicitly called. At apply time, the system commits status to "applied" in the database before mutating the live store — a commit-before-mutate pattern ensuring no partial state on failure. When multiple high-scoring stories are harvested together, the LLM is told the peer count so cross-story common patterns are upweighted as stronger rule candidates.

III.Informal Claims
  1. Claim 1 — Independent (Method)

    A method for adaptive voice rule generation comprising: mining edit diffs from temporal beat-version history, author directives, and finished prose text; distilling generalizable prose style rules via LLM inference; staging all outputs as proposed in a change log before any live store mutation; and committing status to the change log before mutating the live rule store, such that no partial state can arise from interrupted application.

  2. Claim 2 — Temporal Diff Evidence

    The method of claim 1, wherein edit evidence is derived from a system-versioned temporal table recording all versions of each narrative unit, enabling reconstruction of original-generated vs. final-author text for any unit with multiple versions.

  3. Claim 3 — Cross-Story Upweighting

    The method of claim 1, wherein the LLM distillation prompt is informed of the number of peer stories being harvested simultaneously, causing patterns common across multiple stories to be weighted more heavily than single-story observations.

  4. Claim 4 — Score-Triggered Automatic Harvest

    The method of claim 1, wherein exceeding a configured review score threshold automatically triggers the harvest process, creating a feedback loop between quality evaluation and generation rule refinement.

Eight-Dimension Emotional Rubric Scoring at Narrative Beat Level:
Register-Adaptive Criteria with Blocking Dimensions and Per-Beat Curve

Date2026-07-16
ClassificationSoftware / AI Systems / Quality Evaluation
Abstract

A system for scoring the emotional quality of narrative units across eight dimensions simultaneously via parallel LLM calls, with a universal 0–4 scale (0=absent, 1=asserted, 2=mixed, 3=embodied, 4=instrumental), at least two blocking dimensions that file quality findings when scored at or below a threshold, and register-adaptive scoring criteria derived from the story's detected prose register.

I.Field

Automated quality assessment of AI-generated narrative — specifically, per-beat multi-dimensional emotional scoring with register-specific evaluation criteria and automated quality finding generation.

II.Key Mechanism

Eight EmotionalDimension values are scored simultaneously via parallel LLM calls (temperature 0.1): WantNeedDivergence (BLOCKING) — gap between on-page Want and arc-level Need; TheUnsaid — meaning in withheld content; ObjectsAndGestures — tenderness through physical objects rather than stated feeling; RegisterShiftAsInstrument — temperature shifts on cue; EarnedInteriority — rare, load-bearing interior lines; RelationalSubtext — power/evasion dynamics in dialogue; CostFeltNotAsserted (BLOCKING) — price of wins felt rather than stated; ContradictionAndAmbivalence — gap between felt and shown.

The universal 0–4 scale anchors are identical across dimensions: 0=Absent (flat or stated), 1=Asserted (labeled), 2=Mixed (inconsistent), 3=Embodied (through behavior/object/silence), 4=Instrumental (the dimension IS the emotional work). Register detection from the story's bible text maps to one of GREY/VULTURES/CODA/JOY/SORROW/Fantasy and injects distinct score-4 criterion descriptions per dimension — for example, GREY's CostFeltNotAsserted score-4 criterion is "the gap between what the system records and what it cannot" rather than character affect. Blocking dimensions scoring ≤1 file FindingsService entries with severity High (score=0) or Medium (score=1). A pass 2 produces a per-beat emotional curve written to Beat.EmotionalScore.

III.Informal Claims
  1. Claim 1 — Independent (Method)

    A method for emotional quality scoring of narrative units comprising: evaluating eight emotional dimensions simultaneously via parallel LLM calls; applying a four-point universal scale where 0=absent, 1=asserted, 2=mixed, 3=embodied, and 4=instrumental; designating at least two dimensions as blocking such that scores below a threshold automatically generate quality findings; detecting a prose register from story metadata and injecting register-specific scoring criteria for each dimension; and computing an aggregate score as the mean of dimensional scores.

  2. Claim 2 — Register-Adaptive Criteria

    The method of claim 1, wherein scoring criteria for the score-4 anchor of at least one dimension are drawn from a register-specific mapping, such that the definition of instrumental emotional quality differs between register classes.

  3. Claim 3 — Per-Beat Curve

    The method of claim 1, wherein dimensional scores are aggregated and written to each narrative unit record, enabling trend analysis of emotional quality across a story's full arc.

  4. Claim 4 — Character Context Enrichment

    The method of claim 1, wherein each dimension's evaluation prompt is enriched with the protagonist's Want, Need, Wound, and Flaw from an emotional ledger, grounding scoring in the story's structural character arc rather than the beat alone.

Multi-Provider Continuity Claim Extraction with Triple Validation:
Snippet-Verified (Entity, Predicate, Object) Triples with Three-Outcome Upsert

Date2026-07-16
ClassificationSoftware / AI Systems / Knowledge Extraction
Abstract

A system for extracting narrative continuity facts as structured (entity, predicate, object) triples from prose text, distributing extraction across multiple LLM providers, validating each candidate by confirming its source snippet is a literal substring of the source text, grouping by normalized triple, applying a minimum-voter threshold, and classifying each accepted triple as NEW, CONFIRMED, or CONTRADICTED based on prior state.

I.Field

Narrative continuity verification — specifically, methods for extracting structured factual claims from prose and validating them against a persistent entity state store to detect contradictions introduced by generative AI.

II.Key Mechanism

Each LLM provider is instructed to extract atomic assertions as a JSON array specifying: entity_name (exact as it appears in prose), predicate (short snake_case key, e.g. weapon_carry_location, lives_at), object (concise value), snippet (≤200-char exact quote), voice (narrator/character/inner_monologue), and confidence (low/medium/high). The snippet validation step requires that snippet exist as a literal substring of the source text — eliminating hallucinated citations that did not originate in the prose.

Valid candidates are grouped by a normalized key (entity_name.lower(), predicate.lower(), object.lower()) with whitespace compression. A minVoters parameter filters candidates seen by fewer than N providers, providing agreement-gated acceptance. Each grouped candidate is entity-resolved through a priority chain (character → place → faction → corponation → generic entities table). ContinuityService.Upsert() returns NEW (first seen), CONFIRMED (same predicate and object seen again), or CONTRADICTED (same predicate, different object) — enabling detection of facts that changed between story beats without requiring a full comparison pass.

III.Informal Claims
  1. Claim 1 — Independent (Method)

    A method for narrative continuity tracking comprising: distributing a structured claim extraction query across multiple LLM providers; requiring each extracted claim to specify a source snippet; validating each candidate by confirming the snippet is a literal substring of the source text; grouping candidates by normalized (entity, predicate, object) triple; applying a minimum voter threshold; resolving entity names through a priority chain of typed entity repositories; and classifying each accepted triple as NEW, CONFIRMED, or CONTRADICTED.

  2. Claim 2 — Contradiction Detection

    The method of claim 1, wherein CONTRADICTED status is assigned when the predicate of an incoming claim matches a prior record for the same entity but the object value differs, identifying facts that changed inconsistently between narrative units.

  3. Claim 3 — Entity Record Extraction

    The method of claim 1 applied to structured entity records rather than prose text, wherein scalar string fields below a length threshold are walked directly as high-confidence claims and prose-style fields are submitted to the same multi-provider extraction pass.

Gateway/Sequel Regime Detection with Parallel Commandment Evaluation:
Auto-Detection, Universe-Conditional Injection, and Plant/Payoff Enrichment

Date2026-07-16
ClassificationSoftware / AI Systems / Quality Evaluation
Abstract

A quality assurance system that automatically detects whether a story occupies a gateway or sequel position in a narrative series by inspecting the presence or absence of a predecessor story identifier, loads a distinct set of codified commandments for each regime, evaluates all commandments in parallel via LLM, enriches plant/payoff-related commandments with live registry data, and conditionally injects universe-specific commandments based on the story's universe identifier.

I.Field

Story-position-aware quality assurance for serialized AI-generated narrative — specifically, methods for applying different quality criteria based on whether a story introduces a series universe or continues it.

II.Key Mechanism

Regime detection from a single field: Node.PreviousNodeId == null selects 8 Gateway Commandments; PreviousNodeId.HasValue selects 8 Sequel Commandments. Each commandment is an independent parallel LLM call returning status (pass/warn/fail), evidence (1–2 sentences citing specific prose), and fix.

Gateway commandments enforce: world-texture-led entry (open_grounded), in-register first-mention glossing without dumps (gloss_in_voice), full term before acronym (acronym_after_term), single felt character vulnerability (human_crack), a quiet gesture after plot concludes (land_past_handoff), and re-read reward. The reread_reward and reward_long_memory commandments are enriched at evaluation time with the live PlantPayoff registry for the node, providing factual evidence rather than asking the LLM to infer plant/payoff presence. Universe-specific commandments (e.g. glmz_five_pillars) are appended conditionally based on node.UniverseId — ensuring universe-specific quality criteria never contaminate stories from a different fictional universe. Long manuscripts are clamped keeping the first and last 50,000 chars of texts exceeding 100,000 chars, preserving evidence for both entry and ending commandments.

III.Informal Claims
  1. Claim 1 — Independent (Method)

    A method for story-position-aware quality assurance comprising: automatically detecting a gateway or sequel regime from the presence or absence of a predecessor story identifier; loading a distinct commandment set for each regime; evaluating commandments in parallel via LLM, each returning status, evidence, and fix; enriching commandments related to narrative reward with live plant/payoff registry data; and conditionally appending universe-specific commandments based on the story's universe identifier.

  2. Claim 2 — Live Registry Enrichment

    The method of claim 1, wherein at least one commandment's evaluation prompt is enriched at query time with the live contents of a plant/payoff registry for the story under evaluation, providing factual evidence rather than requiring the evaluating model to infer plant/payoff presence from prose alone.

  3. Claim 3 — Universe-Scoped Injection

    The method of claim 1, wherein universe-specific commandments are appended to the commandment set only for stories whose universe identifier matches a configured universe identifier, ensuring cross-universe contamination is structurally impossible.

  4. Claim 4 — Length-Adaptive Clamping

    The method of claim 1, wherein manuscripts exceeding a length threshold are clamped by retaining the first and last N characters, preserving prose evidence relevant to both entry-oriented and ending-oriented commandments.

Deterministic Universe-Scoped Deprecated-Noun Enforcement:
Whole-Word Boundary Scan with Chapter-Child Traversal and No LLM Inference

Date2026-07-16
ClassificationSoftware / Narrative Computing / Quality Assurance
Abstract

A deterministic system for enforcing canonical naming consistency in narrative generation — maintaining a universe-scoped registry of deprecated-to-canonical name mappings, scanning all enabled narrative units within a story node and its chapter children via whole-word boundary checks, reporting violations with ±40-character context snippets, and requiring no LLM inference at any stage.

I.Field

Canonical naming consistency in AI-assisted long-form narrative generation — specifically, deterministic (non-probabilistic, non-LLM) methods for enforcing entity name standards across large prose corpora spanning multiple fictional universes.

II.Key Mechanism

The DeprecatedEntityNames table stores universe-scoped rename rules: DeprecatedName, CanonicalName, Notes, optional EntityId linkage, and UniverseId. All rules are filtered to the active story's UniverseId — a GLMZ rename rule can never flag a Fantasy-universe beat.

The scan walks all enabled beats from the story node itself plus one level of chapter children (populated via ParentNodeId lookup), covering both flat story nodes and book-mode nodes whose prose lives in chapter sub-nodes. For each beat's text, each rule is applied via case-insensitive IndexOf with explicit whole-word boundary checks on both sides: !char.IsLetterOrDigit(beat.Text[idx - 1]) and !char.IsLetterOrDigit(beat.Text[idx + rule.DeprecatedName.Length]). One match per rule per beat is sufficient. Each violation captures BeatId, BeatNumber, DeprecatedName, CanonicalName, and a snippet of ±40 characters around the match. The report exposes an IsClean boolean for use as a publish gate.

III.Informal Claims
  1. Claim 1 — Independent (Method)

    A method for canonical naming consistency enforcement in narrative generation systems comprising: maintaining a universe-scoped registry mapping deprecated names to canonical names; scanning all enabled narrative units within a story and its chapter children; applying whole-word boundary character checks on both sides of each candidate match; and reporting violations with a context snippet, without any LLM inference at any stage of the process.

  2. Claim 2 — Universe Scoping

    The method of claim 1, wherein all rename rules are filtered to the active story's universe identifier before scanning, structurally preventing rename rules from one fictional universe from flagging narrative units belonging to a different universe.

  3. Claim 3 — Chapter-Child Traversal

    The method of claim 1, wherein the scan traverses one level of chapter children via parent identifier lookup, covering both flat story nodes and hierarchical book nodes without requiring separate invocations for each structural variant.

  4. Claim 4 — EntityId Linkage

    The method of claim 1, wherein each rename rule may optionally link to a structured entity record, enabling the rule registry to remain synchronized with entity renames propagated through the entity management system.
